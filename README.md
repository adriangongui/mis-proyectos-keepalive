# Supabase Keep-Alive 🏓

Prevents your free-tier Supabase projects from pausing due to inactivity (7-day limit).

One GitHub repo, one workflow, unlimited projects. Runs every 3 days via GitHub Actions.

## Setup

### 1. Create the `keep_alive` table in each Supabase project

Go to **Supabase Dashboard → SQL Editor** and run this for each project:

```sql
CREATE TABLE IF NOT EXISTS keep_alive (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  pinged_at TIMESTAMPTZ DEFAULT NOW()
);

ALTER TABLE keep_alive ENABLE ROW LEVEL SECURITY;
CREATE POLICY "Allow keepalive" ON keep_alive FOR ALL USING (true) WITH CHECK (true);
```

### 2. Add your projects as a GitHub Actions secret

Go to your repo → **Settings** → **Secrets and variables** → **Actions** and create a secret named `SUPABASE_PROJECTS`.

Value is a JSON array:

```json
[
  {
    "name": "my-app",
    "url": "https://abcdefghijkl.supabase.co",
    "key": "sb_publishable_..."
  },
  {
    "name": "side-project",
    "url": "https://mnopqrstuvwx.supabase.co",
    "key": "sb_publishable_..."
  }
]
```

**Where to find these:** Supabase Dashboard → Your Project → Settings → API

- `url` = Project URL
- `key` = Publishable key (`sb_publishable_...`) or legacy anon key

### 3. Done

The workflow runs every 3 days automatically. To test immediately:

```bash
gh workflow run "Supabase Keep-Alive"
```

## Adding a new project

1. Create the `keep_alive` table in the new project (Step 1 above)
2. Update the `SUPABASE_PROJECTS` secret — add another object to the JSON array

No code changes needed.

## How it works

- Uses the Supabase JS client to insert a row into `keep_alive` in each project
- Cleans up old rows automatically (keeps last 5)
- Real database writes count as activity — prevents pausing
- Pings all projects concurrently (~1 second total)
